- `botd/src/redact.ts` (`redactText`): redact a path such as `/home/fake-redact-user/project`; the username remains visible. Home paths in diagnostics or events can disclose user identities.
- `botd/src/session.ts` (`handleLine`) and `botd/src/daemon.ts` (`onOutput`, `onResume`): send an `echo` command to the fake child with credentials in text, tool arguments, or permission details. The original payload is sent to the client and stored in the replay ring unredacted. Live and reconnecting clients can receive credentials. The daemon does not currently write session event logs under `BOTD_HOME/sessions`.
- `botd/src/session.ts` (`onStderr`) and `botd/src/daemon.ts` (`onError`): send the fake child a `stderr` command containing a credential. The resulting `child_error` frame includes it verbatim, exposing credentials to clients.
- `botd/src/session.ts` (`start`) and `botd/src/daemon.ts` (`table`, `persist`): open a session with a nonexistent command whose path contains a fake key. The spawn error frame and `sessions.json` contain the key verbatim. Clients and readers of the session table can obtain credentials. Normal child exit produces no error message in this implementation; the spawn error is the available child-process error path.
- `botd/src/daemon.ts` (`persist`, `log`): configure a session table path containing a fake key beneath a regular file, then open a session. The filesystem error is passed verbatim to `onLog`, exposing the key to diagnostic log consumers.
